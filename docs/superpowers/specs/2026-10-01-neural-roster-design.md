# 神经网络自动排班：总体设计与分阶段交付规划

日期：2026-10-01。状态：规划草案；本次只整理文档，未训练模型、未修改生产代码。

## 1. 最终产品与本次确认

用户提供设施布局和干员库，包括各干员实际精英阶段、等级。神经网络读取这些条件，生成可编辑、可导出的长期排班；软件执行同一份排班的理论模拟，给出长期日均收益。

用户本次明确选择：**长期日均综合收益最高，以当前计算页面展示的 82 口径为准；撤销旧训练评分标准。**

最终模型须直接生成排班。只训练收益预测器、返回固定组合模板或把现有搜索包装成模型，都不能作为最终交付。

“任意布局＋任意练度”的产品范围是：固定游戏数据与规则版本内，所有游戏合法、软件能够完整解释的设施布局和实际练度组合。支持任意已知干员子集，包括极小库、混合练度、缺关键组合成员、缺跑单干员，以及合法的非主流布局。最终范围不能只列 243、252 等模板。

结构合法性由确定性规则保证；排班质量由训练及独立评估保证。一般场景不能凭神经网络声称全局最优。界面应称“当前找到的最高收益方案”；只有有穷举或有效最优性证书的小问题才能给出全局最优结论。未来新增干员、未知技能和新设施需要更新规则并重新验收。

## 3. 唯一评分合同与执行条件

新目标标识建议为 `mower-report-82-ideal-v1`。它与已撤销的旧训练目标不兼容。

设各项均已按实际采样小时折算为日均：

```text
score82 = EXP
        + 0.8 × (物理赤金产出价值 + 特殊订单虚拟赤金价值)
        + 0.2 × 订单龙门币

物理赤金产出价值 = 赤金产出件数 × 500
每张非合成玉订单的虚拟赤金价值
    = max(0, 订单报酬 - 订单需求赤金件数 × 500)
```

实现直接调用 `mowerReportMetrics(report).mower82`，不在 Python、模型端或 UI 另抄公式。虚拟赤金属于报表估值，不进入物理赤金库存，也不能再额外加一次特殊订单奖励。此指标是用户指定的加权产出指标，不是现实现金净利润。

所有训练、教师、精修、模型排名与最终展示必须采用相同目标和执行条件。旧标签只可保留原始输入作重新评价的素材；旧分数和旧奖励必须剔除，不能改文件标签后直接复用。相关旧模型需要重新训练或在新奖励下重新训练并完整验收，不能作为兼容的新模型发布。

为了让用户只填布局和干员库就能使用，其他条件由软件提供明确默认值，并保存在结果中：

| 项目 | 首版设计 |
| --- | --- |
| 跑单 | 固定理想跑单 `ideal`；其他执行方式另立 profile，不能混入此模型数据 |
| 收益类型 | `potential`，沿用当前页面理论产出模式；材料无限、Party Time 关闭 |
| 配方、设施等级与宿舍氛围 | 场景输入固定；缺氛围时采用软件明确的默认值并展示 |
| 实际练度 | 严格来自用户；不补人、不升练度、不叠加同槽技能版本 |
| 休息阈值 | 保留旧方案中的独立策略约定：2 实体电站 0.65，3 实体电站 0.50；不是收益折扣。其他合法电站数量暂采用显式默认 0.65，进入专项验证 |
| 普通执行参数 | 冻结软件的急救、返班、宿舍和菲亚参数，记录 profile；后续参数条件化须重新训练/验收 |
| 无人机 | 首版保留仅加速制造的已有约定；标准赤金/中级记录基础工作量等价不能外推到所有低级配方。目标按已验证规则确定并记录 |
| 初始状态 | 长期模型可使用明确的初始心情默认值；暖机消除初始影响须验证。用户提供当前心情时保留并参与复核 |
| 暖机/采样 | 3 天/7 天作为初始评价窗口，最终候选逐步延长，不能称固定窗口为长期收敛证明 |

源石碎片、合成玉或功能设施资源不能静默成为零分标签。最终覆盖这些合法布局时，必须先提供相应物理产出与有效的评分域说明；如 82 本身不评价某类资源，明确标为“该资源不计入 82”，使用固定的次级规则处理并列，不声称优化其未定义价值。未实现机制属于覆盖缺口，不能以这一说明冒充已支持。

## 4. 输入、输出与错误合同

### 输入

- `layout`：实际房间标识、设施类型、等级、固定配方、宿舍氛围、合法工位、功能设施及耗电条件。
- `inventory`：实际持有干员及精英阶段、等级；统一名称/ID关联，并解析为每次计算独立的有效技能快照。
- `executionProfile`：计分版本、理想跑单、无人机与休息参数、初始状态、规则/GameData 版本。
- `constraints`：可选固定工位、禁用干员和用户策略约束；无这些条件也能生成完整方案。

必须区分：未传干员库、明确传入空库、非法干员库。用户已提供库时只能使用库内人员，不能回退全员满练度。设施布局由用户锁定，模型不能通过改设施、改等级、改配方、提高练度来提高分数。

### 输出

生成标准 `RosterWorkspace`，包括主力、普通候补有序列表、组合、宿舍常驻/Free/空位、中枢、发电站、产生收益联动所需的辅助岗位、专用跑单候选、菲亚目标及执行器支持的主配置策略。普通策略运行时交给现有调度器，模型负责生成配置而非实时控制游戏。

初版自动生成沿用“主表＋候补＋执行策略”的合同，不生成任意条件副表。已有软件能导入/执行部分副表，不代表模型已能生成副表。若后续验收发现主表策略空间存在明确收益上限，作为独立版本加入受限的条件策略语言和执行测试。

返回排班、收益分项、当前页面 82、完整性状态、模拟窗口/种子、模型版本、目标版本、规则版本、生成来源、候选数、仿真次数、耗时和诊断。最终复核与导出的必须是同一份排班；导出后再补人、改列表或改配置，必须重新计算。

状态区分：

| 状态 | 含义与处理 |
| --- | --- |
| `VALID` | 输入合法、排班合法、覆盖和完整窗口均通过，可排名和训练 |
| `PARTIAL_VALID` | 人少导致合理空岗等已完整模拟的方案；是否可训练取决于已明确的部分排班合同 |
| `INVALID_INPUT` | 超供电、非法等级、重复库条目等，指出具体输入问题 |
| `INVALID_ROSTER` | 生成动作或最终排班违法；用于合法性改进，不能当有效收益标签 |
| `UNSUPPORTED_RULE` | 未量化规则或未支持策略，进入机制覆盖队列 |
| `SIMULATION_FAILED` / `INCOMPLETE` | 故障、超时、事件停滞或窗口未完成；隔离，不能以零分更新收益模型 |
| `NO_VALID_CANDIDATE` | 本次生成预算内没找到有效方案，不等于证明没有可行方案 |
| `CANCELLED` | 保留已经完成复核的最好结果，不能伪造其余候选的收益 |

确实完成且产出为 0 的方案是有效数值；失败返回 0 的现有内部摘要不是这种样本。

## 5. 推荐架构与其他方案

推荐 **可变长度集合/关系编码器＋受约束的逐步排班解码器＋软件模拟复核**。

```mermaid
flowchart LR
  U[布局与实际干员库] --> C[校验与当前技能快照]
  C --> E[干员/设施/联动编码]
  E --> P[神经网络逐步生成排班]
  P --> V[动作约束与最终校验]
  V --> S[现有排班与生产模拟器]
  S --> R[当前页面82与完整性检查]
  R --> O[排班导出与收益报告]
  S --> T[训练奖励与模型更新]
  T --> P
```

| 方案 | 优点 | 不作为首选的原因 |
| --- | --- | --- |
| 受约束的策略生成模型，推荐 | 直接满足最终产品；可变干员库、布局和策略；反馈来自模拟器 | 要建设动作协议、可信评价与泛化测试 |
| 收益预测器＋传统搜索 | 容易用于加速筛选 | 排班仍由搜索产生，不能独立满足用户目标；可作辅助模型 |
| 仅靠随机初始化策略强化学习 | 无需已有排班标签 | 大动作空间和稀疏终局奖励使初期探索困难；适合作为受控对照和后续主训练 |

### 编码器

干员使用可变长度集合，不把固定序号或名单位置当作能力。每名干员特征包括身份辅助嵌入、实际已解锁技能、技能适用设施/配方、参数、心情语义，以及联动所需的国家/组织/小队/指定对象等关系。

国家使用 `nationId`，组织使用 `groupId`，小队使用 `teamId`；它们是不同集合，不能混作一个阵营计数。指定干员关系与技能类别关系另外编码。具体成员由当前 GameData 生成，不把旧名单写死为永久规则。

设施特征包括类型、等级、岗位容量、配方、宿舍恢复条件和位置语义。利用注意力或关系编码处理跨站条件、中枢、发电、宿舍等全局影响。单个“效率百分比”不足以表达容量转换、清零、复制、暖机、特殊订单或心情交换。

练度必须显式保留，同时使用确定性解析出的技能快照。技能解锁之间的很多等级拥有相同基建能力，可按有效技能状态减少样本浪费；只有确认为收益等价的状态才允许合并。每个解锁点前一级/当天解锁等级/后一级均需专项测试。

首个候选模型建议隐藏维度 128 或 256、4 层左右编码、轻量解码；这些只是原型比较参数，不是提前确定的最终容量。先比较技能特征主导模型与只含身份嵌入的弱基线，证明模型不是记忆固定人名搭配。

### 解码器

动作从有限协议中选择，按阶段填写：宿舍和辅助支持、主力、换班分组、普通候补、跑单候选、菲亚目标、优先级等策略。优先阶段顺序只是原型方案，需要用整表评价检查是否过早占用关键人员；可加入小范围回看或重生成。

每一步根据当前配置屏蔽非法动作，包括池外人员、实际重复占岗、超工位、违反锁定和非法列表语义。允许 `EMPTY`、`FREE`、`END_LIST` 等状态。没有该设施技能不必然禁止上岗；关键是按照真实技能模拟，而不是假造收益。

候补出现多次不等于同时占岗，菲亚目标可以引用当前主力，专用跑单列表不能当普通轮班候补。普通候补资源竞争须按执行器实际的动态语义验证，不能简单规定整个 JSON 中每名干员只出现一次。

局部合法动作不保证剩余步骤存在可行补全。增加剩余岗位/候补/恢复床容量检查、有限回溯和有限重采样，最后走完整物理和动态校验。把随机探索中的非法惩罚与模拟器故障明确分开。

模型自己选择组合和支持人员；组合目录仅用于辅助样本/对照，不成为硬性的唯一候选集合。组号规范化消除纯命名差异；有序替补、跑单候选、宿舍槽位、实际房间顺序不能随意排序。

## 6. 训练环境与机制覆盖

保留 TypeScript 模拟器作为唯一规则实现。Python/PyTorch 负责模型和优化，通过常驻 Node 进程或进程池以版本化 JSONL 协议调用评价器，避免每张排班重新启动进程。

请求带请求编号、场景、完整排班、评价预算、种子与版本。响应带状态、分项、当前页面 82、实际窗口、诊断和证据引用。训练数据缓存必须包含目标、规则、技能快照、布局、执行参数、排班与随机种子；房间/列表的语义顺序保留。不能只以干员名字或布局代号作为键。

建立“原始技能/条件 → 可执行解释 → 解码字段 → 模拟事件 → 独立用例”的覆盖矩阵，优先补会影响选择的机制。包含：

- 技能版本替换与不同设施的低阶段技能；直接效率与容量、复制、清零及暖机。
- 同站指定对象、跨站支持、国家/组织/小队与技能类别计数。
- 普通候补、整组原子换班、床位竞争、返班、0 心情存在性与工作技能失效的区别。
- 菲亚心情交换的真实有序目标语义；特殊订单当前已解锁版本。
- 无人机充能、共享持有量、上限和溢出；单位、订单抽样与收取假设。

未解释的技能不能从库中悄悄删除，也不能以“可训练”掩盖未知收益。未覆盖场景单独计数并驱动规则补齐。在已声明的发布域中，覆盖通过率必须达到 100%；扩展到完整游戏已知域仍需逐项完成。

模拟成功只是第一层证据。需有公式/边界测试、实际运行状态不变量、冻结排班复验和外部已确认观察。模型可能利用模拟器漏洞，特别要检查重复收益、虚拟赤金入库存、心情被重置、无床无限恢复、无人成岗等异常。

## 7. 场景数据与泛化设计

先建立场景并划分训练/验证/测试，再生成该场景的候选排班。不能把同场景的不同排班或排列版本随机分到不同集合。

场景分层维度：

| 维度 | 必须包含的层次 |
| --- | --- |
| 布局 | 全部合法设施数量组合、各级混配、非主流组合、供电刚好等于耗电、不同宿舍/功能等级 |
| 干员库规模 | 空/极小、小、中、大、全库；比例按真实范围与困难场景共同设计 |
| 练度 | 全低练度、混合练度、满技能、每个解锁阈值两侧 |
| 联动 | 完整、缺一个/多个成员、竞争同一支持工位、相同局部技能而全局条件不同 |
| 调度 | 少床、少替补、缺宿管、缺跑单人员、多个跨站组、菲亚可用/不可用 |
| 任务配方 | 固定赤金/记录/贸易混配；其他配方随规则和计分说明完整后加入 |

生成布局时先检查设施位置、类型、数量、等级、耗电和配方解锁，再取干员库。训练混合合法随机分布、真实脱敏场景、边界场景和当前模型失败场景，不能完全靠均匀随机或只靠强组合模板。

真实用户库以本地生成/脱敏为默认；不需要收集账号密码或游戏登录数据。记录分布版本、抽样种子、去重键、拒绝原因和重试上限。

测试至少分为：同分布独立场景；未见布局结构组合；未见干员组合；大于训练常见规模的库；极低练度与技能边界；小库/休息资源紧张；对现有技能特征可解释的留出干员测试。未来新增机制单独报告，不能与已知干员的新组合泛化混称。

划分同时使用精确场景键和更高层的库/布局家族键，防止只改一名干员或一级练度造成近重复泄漏。干员输入顺序可做排列增强；房间的运行语义顺序不能为了数据去重而改写。

首轮建议用约 1,000 个分层场景测合法率、有效模拟率和成本；通过后建设约 10,000 个场景的可学习验证集，再按验证结果扩到更大训练分布。数值是工作预算起点，不是足够泛化的样本量结论；每场景候选数、有效标签数量和在线强化学习调用量另外记录。

## 8. 从随机权重开始的训练路线

### 阶段 A：小问题证明可学习

在保留实际规则的小干员库/少岗位场景，枚举受限排班空间，取得确切最优或明确的高质量候选。建立随机合法生成、简单技能贪心、现有智能排班三组基线。

模型从随机权重初始化，直接输出完整排班；先验证能学习所有权、岗位语义、基本收益选择和技能解锁差异。受限空间的最优不代表完整策略空间最优，报告必须注明枚举了哪些字段。

### 阶段 B：辅助模仿与排序学习

用小问题最优方案、现有生成器、多起点搜索及独立候选产生训练素材，在新 82 口径下全部重新模拟。教师输出只是最好已发现方案，不能标成全局最优真值。

为多种收益相近且都有效的排班提供多答案，避免只认一张表。模仿帮助学习配置语法和基本组合，辅助排序学习同一场景的高低收益。收益预测头可帮助候选筛选，但它不负责最终报表。

如果要求完全不用教师数据，阶段 B 可以关闭；从阶段 A 的小问题在线探索开始，逐步扩大动作空间。这仍需真实收益反馈，不能保证初期训练同样快。

### 阶段 C：模拟奖励的策略学习

使用带基线的策略梯度作为首选原型；动作是逐步构造配置，整张排班的当前页面 82 是终局奖励。采用同场景贪心策略/历史独立基线减去分数尺度，防止大库天然高分压过小库学习。归一化用于梯度，最终排名使用未归一化的报表分。

不要求模拟器可微，收益通过策略梯度更新神经网络。保持有效探索、逐步增加布局和策略复杂度，加入反复失败或性能差的场景，同时保留原分布以防遗忘。固定策略约束之外不加入偏离收益目标的隐式奖励；如需偏好少换班，作为并列选择规则或用户明示目标。

合法动作掩码必须进入训练与推理同一分布。若使用 PPO，保存当时掩码和动作概率并遵守其数据更新条件；首版无需为了算法名称复杂化成实时游戏控制。

训练批次的模拟故障/未覆盖样本不参与收益更新。结构无效可训练合法性，但不能把故障误判成该布局收益差。所有候选无有效分数时跳过该批并汇总原因。

### 阶段 D：反复评估与停止

以固定验证集选择模型，最终测试集只作锁定后的验收。至少多个训练随机种子检验稳定性。保存权重、优化器、随机状态、场景分布、评价缓存索引与版本，支持断点恢复和取消。

停止条件由验证集收益/尾部场景表现、无改善耐心阈值、有效模拟率异常和资源预算共同决定；不能按训练集 reward 上升就宣称完成。

## 9. 推理、复核与软件集成

提供两种明确的质量路径：

1. **直接生成**：模型贪心解码一张表，校验后由软件计算收益。这一路独立评估，证明模型本身有排班能力。
2. **质量优先**：模型产生若干不同候选，软件在相同条件下模拟并选择；可再进行有限局部精修。生成数初始可比较 8/16/32，不事先承诺固定耗时。

精修是可选质量增强，不能掩盖直接生成模型不合格。正常流程必须由模型提出排班；现有算法只作为公平对照或明确标记的回退。模型不兼容/生成全部失败时，可显示传统算法结果，但要标明生成来源。

如对外承诺“与某个已运行基线相比不变差”，必须实际运行该基线、同目标评价并择优；这种承诺是产品组合策略的结果，不能归因于模型单独能力。

UI 顺序为布局与配方确认 → 干员库校验 → 自动生成 → 收益复核 → 查看/编辑/导出。无需用户理解网络层数、训练 loss 或 profile ID。展示设施岗位、主班/候补、宿舍/休息、联动条件、日均经验/物理赤金/虚拟赤金/订单/82及主要假设。修改排班或练度使原收益失效，重新计算后才显示验证状态。

Python/PyTorch 用于离线训练，发布时导出 ONNX，优先利用当前 Vue 应用中的 Web Worker 做本地推理；ONNX Runtime Web 的 WebAssembly 路径为兼容基线，WebGPU 作为验证过的加速选项。原型需先验证动态维度、掩码、解码状态和目标设备算子支持，再决定导出结构。不得要求普通用户安装 Python 或 GPU 工具链才能使用排班。

模型包包含权重、特征词表、目标/规则/动作协议版本、校验和、适用域和评估摘要。模型与 GameData 不兼容时提示更新或回退，不能继续输出可信标签。ONNX 与训练框架用相同输入核对 logits、动作和最终模拟收益；量化须单独重新验收。

## 10. “最合理”与“任意输入”的验收

所有阈值均为建议发布标准，需要原型基准检验，不是现成性能承诺。

| 验收层 | 标准 |
| --- | --- |
| 所有权与练度 | 已输出有效方案中，池外人员/虚构技能/悄悄改练度必须为 0 |
| 布局与实际占岗 | 改布局、超容量、同时重复占岗等硬性违规为 0；电力恰好相等可用 |
| 合法输出可靠性 | 对具有已知有效方案的发布域测试，建议有效结果率 ≥99.9%；其余明确失败，不能输出假成功 |
| 排班动态可靠性 | 疲劳/恢复/候补/组事务不变量通过；阻塞与合理空岗需有清晰合同，不能虚造工休比例 |
| 计分一致性 | 训练、排名、导出再计算的 82 来源一致，误差仅限规定浮点容差 |
| 小规模最优差距 | 在明确枚举空间，建议平均相对差距 ≤1%，高分位差距 ≤3%；零最优分用绝对差距 |
| 大规模直接模型 | 相同评价条件下，相对强基线收益比建议中位数 ≥98%、低端第5百分位 ≥90%；分层分别满足/报告 |
| 质量模式 | 相同模拟调用数与墙钟预算比较收益、退化率、最差案例；只有逐例择优才可承诺不低于已比较基线 |
| 泛化 | 未见布局、组合、低练度、小库和缺跑单成员独立报告，不能只看总体均值 |
| 长期稳定性 | 窗口扩展、独立种子复验后分数和排名稳定；接近候选报告不可区分 |
| 性能 | 模型加载/编码/解码/模拟分开报告中位及高分位耗时、内存；CPU 兼容设备亦通过 |

大规模强基线必须由现有智能排班、多起点搜索和其他候选在新目标下复核构成。报告模型直接输出、模型多候选、模型＋精修、传统基线四组，避免把搜索改进算成网络改进。

特殊订单随机性：同场景候选用统一种子集合减少比较噪声；最终使用未用于挑选的独立种子复验，不靠挑种子抬分。初始建议至少 4 个种子，高波动/近并列候选再增加。

长期性：从 3 天暖机/7 天采样开始，比较延长暖机和采样后的分数与排名；连续扩窗变化低于 0.5% 可作工程稳定标准，但仍不是数学收敛证明。设置最大窗口/事件预算，达到上限仍不稳定则标明未稳定，不能强行给长期成功标签。

变形和边界用例包括干员输入重排、解锁阈值跨越、少一个支持者、实际技能不变的等级变化、池外人被掩码、空库、零收益合法排班、恰好供电、修改候补顺序、缓存中的实际练度变化。房间或候补的语义重排不能当作不变性测试。

“任意”的证据由合法布局覆盖矩阵、每个技能阶段边界、分层库分布与独立留出测试共同提供；不能用有限测试证明所有组合上的最优质量。发布报告明确支持范围、未验证机制和质量分布。

## 12. 成本测量与风险控制

在 P1 测至少分层的 1,000 场景，记录有效模拟率、每次调用成本、长窗口成本、并行收益、事件数与内存。训练耗时近似为“有效评价调用数 × 单次成本 / 实际并行效率＋模型更新成本”，据此确定 CPU/GPU与样本预算。不能在测量前承诺几小时训练完成或固定显存即可泛化。

主要瓶颈很可能是完整模拟调用，而不是小模型前向计算。利用现有并行候选池、完整结果缓存、短窗初筛/长窗复核；短窗结果只作低精度反馈，最终排名以长窗验证为准。辅助收益模型可减少无价值候选，但所有正式输出仍过权威模拟。

| 风险 | 应对 |
| --- | --- |
| 模型记模板，低练度或非主流布局退化 | 技能特征、集合编码、分层训练和留出组合测试；监督与在线奖励并用 |
| 教师搜索把自身盲区传给模型 | 多来源教师、独立小问题最优、持续探索，教师标签不称全局真值 |
| 模型利用模拟器漏洞 | 独立机制用例、动态状态不变量、异常高分审计、冻结真实观察复验 |
| 82 标准再次漂移 | 唯一计分入口、目标版本、数据/模型不兼容检查；全链路同输入复验 |
| 缺人/缺床被强行补满 | EMPTY/Free 状态、动态阻塞合同、有限回溯；无结果与无解分离 |
| 任意 JSON 或无限策略导致不可执行 | 有限动作语言，字段须有实际执行与回归证据后开放 |
| 旧标签/缓存污染新训练 | 新目标独立命名空间，重评价原始输入，旧数值标签剔除 |
| 部署算子不支持或量化影响排序 | P2即验证ONNX导出；WASM基线；逐层与端到端对照，量化另验收 |
