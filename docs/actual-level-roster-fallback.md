# 实际练度散件排班

2026-09-22 修复：自动排班不再要求散件主班和普通替补解锁全部基建技能。

- 组合仍走原有技能准入检查；组合成员不足或技能未解锁时，不虚构组合加成。
- 制造、贸易散件按当前精英阶段和等级的已解锁技能排序，保留对未支持联动的过滤。
- 组合候选无法补齐时，对生产设施、中枢和发电站的主班及独立替补进行统一匹配。优先使用有收益的散件，必要时使用在该设施无技能加成的已持有干员；模拟仍按其真实技能计算。
- 匹配保留已有人员占用，不借用未持有干员，不重复分配普通替补；宿舍空位作为 Free 休息床位。
- 缺少但书或龙舌兰时，只配置实际已持有且已解锁技能的跑单人员。
- 分支数为候选上限，有至少一套有效候选即可进入模拟；完全无法补齐时说明主班/独立替补不足。
- 所有候选仍必须通过动态模拟，不能将生成成功等同于模拟成功。

回归入口：`src/optimizer/inventoryFallback.spec.ts`。覆盖精零一级、缺少跑单干员、锁定工位、空/极小干员池和 24 小时预热 + 72 小时采样。混合练度数据来自用户提供的练度表，仅保留干员代号、精英阶段、等级。

## 2026-10-01：按技能效率选择散件

1. 从实际持有人员中取当前精英阶段、等级已解锁的技能；同一技能槽只保留已解锁的最高版本。
2. 先匹配目标设施，再由计算引擎判断当前配方、设施等级、同站人员及全局条件下的有效技能贡献。
3. 制造、贸易的普通散件按有效技能贡献降序排序，然后选择对应的可用干员。常用组合目录中的人名不参与散件准入或排序优先级。
4. 主班、普通替补以及后续散件优化均使用实际已解锁技能；人员占用、锁定工位、普通替补唯一性与完整组合保护继续生效。

制造、贸易散件仅接纳已支持的加算技能机制。复制、清零、自动化、特殊订单和全局资源组合仍按组合规则评估，未量化的技能不用于效率排名。制造、贸易排序不计通用的进驻基础加成；同一干员的独立技能槽按当前条件合并计算。暖机技能沿用理论上限用于候选排序，最终收益由包含暖机过程的动态模拟验证。发电站比较无人机加成，中枢仍按对全基建的实际贡献评估，不跨设施比较技能描述中的百分比。

验证例：训练室一级时，维伊的制造贡献为 10%，香草为 25%，主班与替补均先选香草。机械师进贵金属站时只计通用暖机的 10%，不计作战记录配方技能。雷蛇从精二改为精零后，其发电技能由 20% 变为 15%，排序缓存必须重新比较，而不能沿用旧技能结果。
