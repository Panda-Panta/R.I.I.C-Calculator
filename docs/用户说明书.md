# R.I.I.C-Calculator 用户说明书

## 1. 定位

R.I.I.C-Calculator 是专为《明日方舟》基建设计的排班计算与 Mower 核心排班工作台。本项目基于 Vue / Vite 技术栈构建，旨在为玩家与自动化脚本用户提供可视化的排班方案编辑、策略编排、格式转换以及基建产出估算投影。

---

## 2. 安装启动

### 环境要求
- Node.js（推荐 LTS 版本）
- pnpm 包管理器

### 常用命令
- **安装依赖**：
  ```bash
  pnpm install
  ```
- **启动本地开发服务器**：
  ```bash
  pnpm dev
  ```
- **生产环境打包**：
  ```bash
  pnpm build
  ```

---

## 3. 界面

工作台整体界面围绕 Mower 排班逻辑构建，主要包含以下功能区域：
- **基建设施布局区**：展示制造站、贸易站、发电站、宿舍、控制中枢及右侧副设施等当前房间状态。
- **排班编辑工作台**：针对选定设施编辑主力干员、按顺序替补队列、组合逻辑与策略参数。
- **导入导出面板**：提供 Mower JSON 文本与 16 二维码组合 JPG 的快速导入与导出操作。
- **收益与交接汇总区**：直观呈现经验、赤金、龙门币贸易、无人机分配及详细交接时间表。

---

## 4. 编辑

工作台支持深度自定义排班方案：
- **主力干员配置**：为每个房间的主工作槽位指派主力在岗干员。
- **按顺序替补**：设置干员疲劳或换班时的候选序列。工作台会完整保存顺序；当前旧计算内核只会生成一对一兼容投影，详见“已知限制”。
- **组合策略**：支持针对关联技能干员（如联动效率组合、制造站技能组）进行捆绑调度。
- **全局替换**：一次替换某个干员在主力槽、替补列表和策略名单中的引用；确认前可查看影响范围。
- **主计划策略**：可编辑令夕模式，以及耗尽换班、满心情休息、休息优先级、常驻等 Mower 主计划名单。副排班专有字段只做兼容保留，不在主界面执行。

---

## 5. 导入导出

工作台全面兼容 Mower 的常用配置交换格式：
- **Mower JSON 导入导出**：点击“导入排班”选择 Mower JSON 文件；点击“导出JSON”保存当前方案。无法执行的兼容字段会尽量原样保留供再次导出。
- **16 二维码 JPG 导入导出**：支持 Mower 社区标准的 16 宫格二维码拼接图片解析与生成，方便在移动端与社区之间分享方案。

---

## 6. 设施推断

为了减少手动配置设施等级的繁琐操作，系统在解析排班时按以下规则自动推断基建设施等级：

1. **人数与等级对应**：
   - 2 人制造站 / 2 人贸易站：推断为 **2 级设施**。
   - 3 人制造站 / 3 人贸易站：推断为 **3 级设施**。
2. **右侧设施**：
   - 排班中存在的控制中枢、会客室、加工站、训练室等右侧设施默认推断为 **满级**；缺失设施按 **未建造** 处理。
3. **电站布局推断**：
   - **2 发电站布局**：已建宿舍推断为 **1 级**；制造站与贸易站按进驻人数推断等级。
   - **3 发电站布局**：已建设施推断为 **满级**。
   - **宿舍是否已建**：导入时按实际宿管判断；只有 Free 或空位、没有实际驻舍干员的宿舍按 **未建造** 处理。宿管不要求一定具有宿舍恢复技能。
   - **未建造设施**：宿舍、训练室及其他房间都可缺省，不计耗电、产出、技能或休息床位，不要求左侧九间设施全部建成。编辑设施等级时可选择 **未建造**；重新选择正等级后可配置干员。已有房间但暂时无人值班与未建造是不同状态。
4. **跑单干员推断**：
   - 1 级或 2 级贸易站跑单：仅推断使用 **但书**。
   - 3 级贸易站跑单：推断使用 **但书 + 龙舌兰** 组合。

---

## 7. 排班规则

- **主力与替补机制**：主力干员优先在岗，当主力因换班周期或心情耗尽下场时，系统按替补列表顺序轮转。
- **菲亚梅塔特殊规则**：
  - 菲亚梅塔在宿舍配置的“替补”并不代表常规轮休替补，而是用于指定其天赋机制下的 **“心情交换目标”**。
- **普通宿管干员**：
  - 提升宿舍恢复速度的常规宿管干员 **无需配置替补**。
- **Free 休息池**：
  - 标记为 `Free` 的槽位作为通用休息池，承载未分配或处于弹性轮休状态的干员。

## 8. 计算与单位

系统根据排班配置进行基建产出试算，核心输出指标包括：
- **经验**：作战记录制造产出与折算效率。
- **赤金**：制造站赤金产出速率与生产总量。
- **贸易**：贸易站龙门币获取效率与订单吞吐。
- **无人机**：无人机自然回复速率及其在贸易站加速或产线中的消耗分配。
- **心情**：全员心情消耗速率、恢复周期及各设施内的动态衰减情况。
- **交接明细**：生成详细的时间序列交接清单，标明每个设施的换班时段、交接干员及状态流转。

### 基本操作

1. 导入现有 Mower 排班，或在设施图中选择房间后逐槽编辑。
2. 查看校验面板：严重错误会阻断计算，普通提示不会阻断。
3. 点击“计算产出”。结果区显示贸易收益（龙门币/日）、作战记录（EXP/日）、赤金（条/日及基础价值）、理论无人机（架/日），并提供房间效率与交接明细。
4. 修改排班后重新点击“计算产出”刷新报告；完成后导出 JSON 或图片备份。

### 数值口径

- 赤金“基础价值”按库存价值展示，不等于已经通过贸易站取得的龙门币。
- 贸易收益与赤金库存价值属于资源流的不同阶段，不应直接重复相加为净收入。
- 当前结果是固定暖机与采样窗口下的长期日均近似，不是首次满心情运行一天的瞬时值。

## 9. 保存

- **本地存储**：在工作台中所作的修改将自动保存在浏览器的本地缓存中，避免刷新意外丢失。
- **文件备份**：建议在完成关键排班编排后，通过导出面板将方案导出为 Mower JSON 或 16 二维码图片长期保存。

## 10. 故障排查

- **16 二维码图片识别失败**：
  - 请确认上传的图片包含完整无残缺的 16 个二维码分片。
  - 避免图片经过过度压缩、旋转或模糊失真。
- **JSON 导入报错**：
  - 检查 JSON 是否符合标准语法，确认未缺少关键字段或存在不匹配的括号。
  - 若错误中出现某个中文干员名，请检查该干员是否被同时作为多个主力；同一候选出现在多个替补列表本身不等于同时在岗。
- **计算按钮没有给出数值**：
  - 先查看校验面板的“严重错误”；供电不足、设施人数超过等级上限或同一干员重复作为主力都会阻断收益汇总。
- **结果与 Mower 或自制表格不同**：
  - 先核对设施等级、产品、主力、替补顺序和跑单等级；若配置一致，差异通常来自当前尚未完整实现的动态宿舍、菲亚梅塔交换、订单快照或库存闭环。
- **环境运行与依赖问题**：
  - 确保 Node.js 版本兼容，若依赖安装异常，可尝试清理后重新执行 `pnpm install`。

## 11. 已知限制

> [!WARNING]
> **关于旧引擎与计算精度的重要声明**：
> 1. **一对一兼容投影**：当前旧计算引擎主要采用一对一兼容投影算法，旨在映射排班框架与估算大体收益。
> 2. **事件仿真引擎状态**：已接入高精度排班离散事件模拟引擎（Schedule Simulation），支持排班编译、普通/跑单候选分流、Free/VIP 休息位、菲亚梅塔交换、逐订单粒度与赤金库存消耗模拟、无人机加速配置等。
> 3. **数值差异**：**排班导入成功仅代表配置语法与结构被系统识别兼容，不等于最终计算产出数值与 Mower 实际运行结果完全一致。** 实际运行效果请以 Mower 实机运行数据为准。

---

## 12. 数据安全

- **纯前端本地运行**：本项目完全在用户本地浏览器或本地开发环境中运行。
- **无配置上传流程**：当前应用在浏览器本地解析排班 JSON、二维码图片并保存工作区；请仍按普通本地文件管理方式妥善保管导出的排班。
