# 自动排班搜索与验证

自动排班优化固定布局下的人员和主替安排，以完整仿真采样窗口内的日均加权产出为最终比较标准。合法占位、已有人员锁定、组合完整、实际技能阶段和恢复容量是约束，不参与收益取舍。现有排班的独立收益计算与本入口分别运行。源码合并、安装备份及验证状态统一记录在 [当前计划](../UPDATE_PLAN.md)。

## v1.1.3 使用入口

Windows 程序与发布信息见 [v1.1.3 发布页](https://github.com/Panda-Panta/R.I.I.C-Calculator/releases/tag/v1.1.3)。在工作台核对实际布局、建筑等级与电力，导入实际持有干员及精英阶段、等级，再点击「自动生成排班」。已有配置人员与锁定会保留，希望重新选择的工位应先清空；不应将验证用的全目录满阶段库存当作自己的库存。

默认保持深度比较与条件副表关闭，核对权重、无人机目标和采样时长后开始。完成后直接查看胜出排班的同次验证报告；「计算产出」用于按收益设置独立重算并生成时间轴。JSON 导出可交给 Mower 使用，导入导出通过不等于已在游戏执行。简要操作见 [README](../README.md#开始自动排班)。

## 默认搜索

1. **构造有限合法主班候选。** 按实际干员库比较完整组合骨架，完成至多三份不同的主替、宿舍、辅助工位和跑单配置。第一份保留为初始表。对已有常驻存在体系，恢复型宿舍支援可作为优先构造起点，自由构造起点仍保留；这是构造偏好，不证明其长期收益更高。暖机与恢复策略在评分前写入，不用未补齐的骨架代表最终主班。
2. **补充有限整队提案。** 复用一个未锁制造房的八人/56队有限域，在保持外部安排、完整组合与策略不变的前提下，至多补两份合法纯主表。这个步骤不生成副表，不放宽暖机或替班要求。
3. **按完整主班产出筛选。** 使用共享的全基地主班加权小时产出，包含实际练度、同站与全局在岗联动。主班更强的新提案与初始表一起验证；初始表已经最强时，次优候选只作按需后备。主替均值、单站人均和混合主替效率向量不能代替这一指标。未量化评分记为未知，全部未知时只保初始表，不补成零收益。
4. **一至两份完整仿真确认。** 对入选候选使用相同预热、采样、种子、无人机目标和权重，默认 24h 预热加 72h 采样。初始表最强时先验证一份，成功完成且评分有限就返回；只有未完成或评分非有限时才验证另一份后备。有更强新主班时比较两份已完成F，最终按日均加权产出选择；同分时优先较高主班评分，再按既有偏好排序。按需预算会跳过部分静态较弱或同分方案，不是长期F支配证明。

直接返回胜出排班及其同次仿真报告。默认不追加主替改写、散件置换或邻域搜索；显式开启的第三阶段会增加比较和完整仿真，不属于上述默认两份范围。旧设置中显式开启的选择保留；`trials`、`simulationTopK` 等旧字段仅兼容保存，不再控制默认完整排班数量。

组合的存在支援与同步恢复分别建模。鸿雪的杜林计数要求实际进驻基建，不能据此要求辅助支援随贸易核心一起休息。内部生成该原子时，factory/train 中明确的杜林存在支援保留主位，不新增贸易恢复组；已有用户组、锁和候补保留。无组加工站/训练室沿用运行时的被动常驻策略，静态替班快照也保持这些实际常驻者。该规则不扩大到其他组合，不增加工作狂或疲劳例外。

后续备用组合也须保护被动辅助主位：自动构造启用 `preservePassiveAuxiliaryPrimary`，不能借完整备用组合把原无组的加工/训练主位挂到生产恢复组。冲突时拒绝整个变体，继续考虑实际支持较少的完整变体；计分读取真正进驻成员，不保留被拒辅助的理论加成。已有明确分组仍按原规则执行。这是自动构造的保守策略，不是把这种原生配置判为游戏非法。

存在支援每个核心落点、人员子集最多三种实际布置：原辅助优先路径、多宿舍恢复路径、只用一名恢复支援的省床路径。恢复排序复用实际技能阶段和同类最高规则，每个新增恢复房保留至少一个真实恢复空位；条件接收者只用于隔离的边际探针，不放入排班或收益。宿舍进驻同样满足鸿雪计数。原有无动态绑定、无候补、实际已解锁他人恢复技能的固定宿管在生成私有副本中保护；显式常驻设置、轮班床和用户锁保留。

完整仿真的重复发现查询使用调用内索引：替班依赖闭包按现有操作员顺序建立分组成员表，替班检查同步阶段按房间/位置保留首位占位者。索引在每次调用时重建，组变更和读房后仍读取最新状态。此处只减少查询工作，不改变换班条件或休息策略；实际生成速度由同输入冷进程验证。

## 持续主班优化（开发分支）

本节选项尚未包含在 v1.1.3 下载包。默认快速生成保持不变；开启「继续比较主班与恢复方案」后，先完成原快速流程，再追加有限的菲亚目标集合、未锁宿管布置和跨房主班候选。默认最多追加 3 次完整仿真，上限 8 次；默认 30 秒预算，上限 300 秒。时间预算在新作业派发前检查，已开始的完整窗口继续运行，不承诺到时立即结束。额外预算不包含初始快速生成和另行开启的深度搜索开销。

「允许自由组合」允许拆解自动构造的内部预设组合，按实际成员重算真实技能加成。现阶段是有界跨房单/双主位交换：最多 6 个房对、64 个提案和 4 个输出，并非全基地无约束枚举；复杂多绑定、跨房恢复组及固定外部引用目前保留。受影响房中含耗尽成员的内部简单同步组，还可提案改为各工位独立恢复，保留原耗尽策略和有序普通替班；涉及用户原组、锁、多绑定或外部恢复排除引用时不拆组。修复提案在原预算内替代同一主位名单的单换提案，不扩大静态预算。输入中已有人员、完整工位、替班顺序及组合继续保护；希望重新安排的原工位应先清空。原方案始终保留，不能将“脱离内部模板”理解为忽略实际库存、技能、主替唯一、暖机或恢复床位。

显式开启自由组合时，额外仿真首先分配给自由候选，再轮转恢复候选与真实组合后的候选。静态产出只排序提案，不因为静态分数高就采用，也不复用父候选的分数。修改后的完整排班使用相同种子、库存、权重、无人机设置与预热/采样窗口重新演算；完整输入缓存可复用已完成结果，不占新的物理仿真次数。

新阶段按同次原生报告核对有效工作、疲劳占岗、休息和闲置；工作占比使用有效工作时间除以完整观察窗口，工休比另用工作时间除以休息时间，不能相互替代。仅完整、有限、严格收益合格、普通疲劳已知为零且没有期末未恢复延期的候选可被新阶段接纳并发送当前最佳快照。基线不合格时可优先采用质量合格的候选；预算内没有合格者则保留原快速结果并明确诊断，不宣称该回退也通过了新门槛。旧 H 预测的贸易误差尚未解决，本阶段直接使用完整 F，不将 H 当作可靠的快速收益排名。

持续优化期间的完整合格快照先暂存，点击「结束优化并保留当前方案」才采用并停止 Worker。用户修改排班、权重或离开页面时丢弃旧任务快照，迟到消息不能写回。可选阶段异常保留最近已完成的排班及其同次报告，不让额外搜索丢失快速结果。条件副表实验与本阶段分别运行。

## 显式深度优化的制造队伍模型

大域制造计算保留在显式深度选项与既有副表实验路径。它从初始表提取支持的制造组，建立完整队伍及组、房间、主替落点；估值前用纯结构动态规划检查组、房间与核心覆盖。周期估值按同一预热/采样窗口、实际技能与心情/恢复策略计算主替兼容轨迹，背景与参考床位固定；再用动态规划和人员冲突分支联合指派，只事务解码已完整量化的列。默认高产主班流程不再无条件支付这次大域枚举和周期估值。

当前联合重分配仅支持已建、生产赤金或作战记录、1–3 工位且每房一个完整换班组的制造站，每个槽位有一个普通物理替班。房号、容量、实际人员和技能阶段都从输入推导，不固定为 243 布局，也不把缺失库存记录补成满练。多绑定、同房拆组、跨多个制造房的复杂核心、永久制造主班、锁定块及固定菲亚梅塔/外部候补引用涉及的块保留原样；固定跨站支持仍保留原房、原位和绑定。

用户原始排班已有完整核心的产品、成员以及锁定人员和位置是强约束。内部构造的其他核心可以整组弃选；同一组合的实际合法产品变体具有相同固定外部核心、同支持组且有共同本地核心时，也允许整体换用变体。共同核心必须完整保留，旧变体独占而新变体不需要的成员可以释放到其他合法队伍。例如内部自动化赤金组可保留固定承曦格雷伊支持、整体转换为合法经验组并释放清流；用户原有赤金组合不会因此被改写。两个完整核心也可以在合法的同一队伍中共存。

队伍枚举、周期估值和指派搜索各有数量、工作量或时间预算。达到预算时明确记录中止原因，只使用已经完整量化的队伍和周期兼容关系；初始可行表继续保留。未完成的枚举不能称完整库，未量化列不能按零收益混入，当前量化子域的最优也不能称原始完整域最优。没有支持域、没有可行指派或解码失败时保留初始排班及诊断。

并行仿真先派发主替初始正耗速较高的任务，以减少长任务留在队尾的等待。该特征仅估计事件密集程度，不参与收益筛选，也不代表运行时间上界。每项作业使用自己的库存与技能阶段；不能评估时保持普通优先级。全部输入、种子及采样窗口不变，完成结果和进度映射回原候选索引，同步入口保持原顺序。

完整候选去重包含设施、分组、恢复策略、候补和顺序。单次任务只缓存完整、有限评分的模拟结果，缓存键包含完整输入及仿真设置，不将旧方案的报告附到修改后的方案。

## 实验选项：联合生成条件副表

该选项默认关闭，后续开发暂缓。v1.1.3 的四布局产出与耗时记录均未启用副表；下列实验路径不属于默认快速主班流程。

在自动排班参数中开启「联合生成条件副表（实验）」后，生成器比较纯主表与附带一张条件副表的配置。开关默认关闭，旧配置缺少该字段时仍走原流程；额外深度比较是另一项独立选项。

联合提案按观察条件跨主表配对轮转，避免四个名额全被首对主表的两种极性占用。正式小候选域还用至多100次共享静态投影优先考虑收益顺序随外部状态交叉的配对；未知或未量化时保留稳定顺序，不把投影当作完整 F。

实验流程保留初始表，准备有限的计算结果、完整生产房主替互补与上下文整队候选，最多对四份纯主表执行完整 F，再对至多四份主副配置执行相同完整 F。已有 deep 流程的调用不包含在这八次预算内。上下文整队提案只处理一个未锁的三工位制造房，最多八名实际可用、已解锁制造技能且非暖机的干员、56个三人队和256次静态投影，输出至多两份互补纯表；静态评分只用于提案，不作为完整 F 的上界或增益证明。所有外部岗位、用户锁及已有完整组合继续生效。

副表仅覆盖完整制造或贸易房间，不改写 `conf`、任意任务或高级设置。触发条件来自不参与覆盖、迁移及绑定闭包的一至两名实际持有干员的在岗设施和可选有效心情；只生成条件成立或其补集两类表达式，进入和退出均使用原生 `AFTER_PLANNING`。不会通过副表把暖机干员变成短时普通替班。无法形成合法互补或观察条件时保留纯主表并记录原因。

两个模式须分别通过实际库存、物理角色、完整组合、床位和编译校验，再运行原生副表控制器与完整收益模拟。仅严格完成、收益完整且超过纯表得分的候选才会胜出，同分保留纯表。最终返回的排班和报告绑定同一份完整输入；生成描述符只存在于模拟作业中，导出的仍是现有 Mower 主副表格式。任务缓存包含工作区、描述符、库存、种子、窗口、权重和其他模拟选项，不能用纯表评分替代联合配置评分。

这是一项有限候选搜索。实际收益取决于库存、外部联动的工休时序、恢复与切表成本；没有合法副表或副表未增产均为正常结果，不能据此保证任意排班改善，也不证明全域最优。源码、计算器模拟、浏览器和真实 Mower 执行的验证状态分别记录在当前计划与本机证据中。

## 暖机与休息

自动生成按实际持有练度和工作设施识别有明确数值暖机机制的技能，为暖机主班追加 `exhaust_require`。制造、发电和伊内丝等明示的线索效率暖机仍正常计算。裁缝、线索倾向等没有明示暖机曲线的机制按最高档处理，沿用既有固定概率/计数模型，不新增暖机损失或自动耗尽要求；用户已有的耗尽配置保留。训练室目前只模拟闲置进驻，不执行训练任务，因此不按训练任务的累计时长技能配置耗尽。

原有人员锁定、整组关系和其他配置保留；显式永久工作人员继续使用其既有策略。组内一个主班采用耗尽策略即可让整组跳过普通心情阈值。多个成员采用耗尽时，由最早需要休息的成员触发整组，因此不保证每个人都恰好耗至零或都达到自己的暖机上限。

普通替班会在原主班回岗时被替换，仅追加耗尽标记不能改变该行为。自动构造和主替调序会避免把暖机干员分配成这类短时替班；已有锁定暖机替班、策略未覆盖的跨设施/跨组主位替换引用或暂不支持的多绑组会报告原因，保留原配置。策略必须在仿真前写入工作区，最终返回同一输入的报告。

## 最优性的范围

默认流程返回**入选高效主班与安全备选中已完成完整仿真验证的较优方案**。静态主班评分用于便宜提案，完整仿真（F）的日均加权产出决定采用哪份表；二者不能互换。保留安全初始表不等于证明任意输入均不低于旧大域数学解，跨布局和库存验证仍是必要验收。

动态规划和冲突分支给出的上界、差距与 `optimalityProven` 仅适用于传入的有限量化系数模型。即使求解完成，也仍受队伍域、固定背景、参考恢复条件和数值积分假设限制；这些上界不是完整 F 的收益上界。要证明完整 F 最优，还需要覆盖全部合法配置并证明模型与完整调度等价，当前实现没有这项证明。

求解代码为本地 TypeScript 模块，不依赖服务端、外部 LP/MIP 求解器或网络加载。同步公开入口仍是同步计算，浏览器界面通过 Worker 执行；预算检查不构成每个宿主环境的实时耗时保证。固定种子控制仿真随机过程，但时间预算下实际完成的计算范围仍可能随宿主负载变化，重现结果须同时保留选中排班、请求和预算状态。

## 比较方法

新旧版本必须固定布局、实际练度、权重、无人机设置、种子以及完整预热和采样窗口。候选预算与是否开启第三阶段属于算法差异，应单独列明，不能用缩短采样或改收益权重制造提升。

记录完整评分、有效与失败候选数、正式模拟调用次数、墙钟耗时、进程 CPU 时间和输入/源码哈希。并行运行其他任务会影响墙钟耗时；模拟次数是独立的工作量指标。中止运行保留部分记录，不作为完整算法结果。单元测试、Node 正式模拟、浏览器 Worker 和真实游戏的证据范围分别说明。

使用 `scripts/benchmark-auto-roster.mjs` 对保存的输入运行正式优化器，输出目录必须尚不存在：

```powershell
node scripts/benchmark-auto-roster.mjs --request artifacts/request.json --out artifacts/roster-comparison/new --concurrency 4
node scripts/benchmark-auto-roster.mjs --request artifacts/baseline-request.json --source-root artifacts/baseline-source --out artifacts/roster-comparison/old --concurrency 4
```

输入包含 `workspace`（或 `base`）、`entries`、`options`，并显式指定 `simulationWarmupHours` 与 `simulationSampleHours`。脚本原样传递选项，只对独立打包源码增加观测，不改源码树、输入或旧结果。`source-manifest.json` 固定实际读入文件和 bundle 的哈希；`events.jsonl`、`result.json`、`summary.json` 保留实际进展、完整结果和统计。仿真引擎调用与候选入口调用分别计数，不相加；直接桥接回退仍计入引擎调用。并发数相同仍不足以消除宿主机其他负载，稳定耗时比较应单独顺序运行。
