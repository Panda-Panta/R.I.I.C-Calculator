## 对齐的决策与保护

| 部分 | 当前实现及核验重点 |
| --- | --- |
| 完整换班预演 | 同时推演到期安排、副表切换、主班休息、纠错、宿舍填充与最终占位，直至稳定；预演循环不提交部分换人，也不消耗原任务。 |
| 副表与床位变化 | 按 alpha 重建有效恢复床池、优先顺序及自动释放组；床位关闭时迁移恢复状态或召回整组，整组候补匹配与床位安排原子提交。 |
| 过程锁 | 完整任务开始执行后保持锁，工作岗已换而宿舍尚未完成时，抑制中间状态导致的副表重入、返岗重建和位置纠错；全部房间完成后解锁。 |
| 延后与异常 | 关键任务可延后剩余宿舍操作并保留锁；房间安排失败按该房间的重试次数延后 1–5 分钟，保留原到期时间、剩余安排及锁。一般异常退出解除锁。 |
| 元数据与返岗 | 按原生床位顺序、个人上下限、整组待命与任务身份构建恢复期限；应用 alpha 路径不采用旧版十分钟返岗稳定性门槛。 |
| 宿舍候选与纠错 | 跳过无观测且无有效估计的候选，保留满心情读数对同伴的保护，按源码共享一小时搜索期限；缓存纠错不把空 Free 床位当作纠错目标。填床重排保留待执行任务与产品预约的宿舍恢复顺序。 |
| 耗尽支援 | 完整匹配、替代候补、受保护干员/床位排除及关闭床位召回，均通过原生决策夹具核验。 |
| 心情观察 | 真实读数高于自定义恢复上限时保留读数和时间戳；无真实读数的床位才按预测更新，避免覆盖实际观察。 |
| 队列保护 | 保留关键任务及显式未来安排；按任务身份合并到期安排，执行前保护宿舍目标和严格心情截止时间。 |

过程锁保护一项完整安排的执行边界。所选 alpha 没有用于强行限制副表切换频率的固定冷却时间。不能为了消除所有短时换班，额外加入与源码不同的副表冷却规则。

## 验证方法

`upstream-manifest.json` 固定 12 个上游文件及各自 SHA-256。本地原生 Python 回放从这些文件提取并执行未改写的决策函数；时钟、已有观察、干员数据、队列和配置作为显式输入，识别、设备点击与生产观测由适配器提供。完整预演对照比较最终安排、普通填床标记、副表条件、保留任务身份，以及失败时原任务是否保持。

原表的 10 次完整预演与原生结果逐项一致，其中第 10 次包括上述循环拒绝。另有一个捕获于约 277.054521 小时的后期循环输入夹具，也与原生拒绝一致。12 个 `mowerAlpha*.spec.ts` 文件共 79 项回归覆盖完整预演与床位、候选、上下限、返岗元数据、任务保护、重试锁和耗尽支援边界。

成功对照只在内存导入副本中把第一个副表触发条件设为 `False`，未覆盖原文件。使用 seed42、赤金无人机、理想跑单、无限材料、整小时暖机、休息阈值 65%、急救阈值 75%、菲亚阈值 90%、菲亚防呆开启、`free_room=false`，完成 72 小时预热与 168 小时采样。该对照会单独采集从第 0 至 240 小时的全部完整预演交给原生决策回放；汇总结果记录于 `acceptance.json`。

## 证据边界

以上证明所列输入与固定条件下的源码决策对齐，以及应用模拟中的占位和心情完整性；不是现场 WebView2 操作、游戏识别、实际账号或 Mower 设备运行验证。生产仍遵循本项目已经确认的理想跑单、无限材料与 Party Time 关闭合同；加工和训练在本场景只保留进驻，不执行实际任务。专精、紧急冻结、产品切换的完整设备流程没有由这组完整预演证明，独立的预约/队列保护夹具也不能代替这些流程的端到端验收。

后期循环夹具来自防呆开启的另一段连续暖机回放所捕获的约 277 小时状态，见 `late-cycle-differential.json`；该相同输入下的原生与移植预演均拒绝循环。这是独立的状态回归，不是最终版本任意长测都会在相同时间停止的预测。不得将正常的 240 小时对照外推成任意排班、任意外部状态、任意时长的全面等价保证。`acceptance.json` 保留这些边界，不将全量测试通过记录为完整游戏循环已复现。
